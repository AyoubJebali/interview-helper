Migration Plan Not yet implemented

Iris Voice Agent → Next.js on Vercel

A full architectural rewrite, not a code port. Vercel's serverless/edge runtime cannot host the current persistent Python pipeline, so the realtime voice loop, RAG store, and UI all change shape.

Current state Python, stateful

  • FastAPI app (agent.py) runs a persistent Pipecat pipeline per WebRTC call
  • Local Whisper STT + local Silero VAD + local Kokoro TTS (ONNX)
  • In-memory ChromaDB for RAG over interview_questions.md (rag.py)
  • LLM via OpenRouter (google/gemma-4-26b-a4b-it:free)
  • Custom WebRTC signaling routes: /api/offer, /sessions/{id}/...
  • Vanilla JS/HTML/CSS client in static/

Why it can't just move Vercel constraint

  • No persistent process — every request is a stateless serverless/edge invocation
  • No GPU / local ML inference (PyTorch, ctranslate2, onnxruntime w/ local models)
  • No in-memory vector DB that survives between requests
  • No long-lived WebRTC media server for the voice call itself
Decided with the user: rebuild the realtime loop on OpenAI Realtime API (browser ↔ OpenAI directly) and move RAG storage to Upstash Vector — both fit Vercel's serverless model cleanly.

Target architecture

The browser owns the realtime media connection directly to OpenAI. Vercel only ever mints a short-lived token and answers small stateless API calls — nothing on Vercel holds a call open.
